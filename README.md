# JUST ONE × BBQ EDITION

BBQで遊べる、JUST ONE風の協力型連想ゲーム。
スマホで同じQRコードを読み込めば、10テーブル並列で同時にプレイできます。

## 特徴

- カードゲーム不要、全員スマホだけで遊べる
- 1ゲーム＝1お題で完結（BBQの合間にサクッと）
- 196題のお題を内蔵（カード番号指定 or ランダム）
- 最大10テーブルが同時にプレイ可能
- プレイヤー名は自動連番（プレイヤー1, 2, 3...）
- 回答者は立候補方式（やる気のある人が手を挙げる）
- 人数は3人〜制限なし
- GitHub Pages + Gist で運用、無料

## セットアップ手順

### 1. このリポジトリをGitHubにアップ

GitHubで新規リポジトリを作成し、このフォルダの中身を全部アップロードしてください。

### 2. GitHub Pages を有効化

リポジトリの **Settings → Pages → Branch: `main` / Folder: `/ (root)` → Save**

数分後、`https://あなたのID.github.io/リポジトリ名/` でアクセスできるようになります。

### 3. GitHub Personal Access Token を作成

1. https://github.com/settings/personal-access-tokens/new にアクセス
2. **Token name**: `just-one-bbq` など分かりやすい名前
3. **Expiration**: イベント当日まで（短いほど安全）
4. **Repository access**: Public Repositories でOK
5. **Permissions** → Account permissions → **Gists** を `Read and Write` に設定
6. 「Generate token」→ 表示されたトークンをコピー（再表示不可！）

### 4. 同期用 Gist を作成

1. https://gist.github.com/ にアクセス
2. **Filename**: `data.json`
3. **Content**: `{}`
4. 右下の「Create secret gist」をクリック
5. URLの末尾の英数字（Gist ID）をコピー
   - 例: `https://gist.github.com/username/abc123def456` → `abc123def456`

### 5. アプリで設定

1. `https://あなたのID.github.io/リポジトリ名/` にアクセス
2. 初回画面でトークンとGist IDを入力
3. 「保存して始める」

設定はブラウザに保存されるので、次回からは入力不要です。

## BBQ当日の運用

### 主催者の準備
1. トークン作成・Gist作成
2. 自分のスマホでアプリにアクセスしてセットアップ
3. テーブル選択 → 「QRで招待」を押す
4. モーダル内で **「🎫 招待URLに切替」** ボタンを押す
5. 表示されたQRコード（or URL）を参加者に共有

### 参加者の流れ（招待URL方式）
1. QRコードを読む（or URLをタップ）
2. **自動でセットアップ完了 + テーブル番号も選択済み**
3. 「このテーブルに入る」を押すだけ
4. すぐにロビーへ
5. 「ゲーム開始」→「やる！」と立候補 → 抽選 → プレイ

### イベント終了後

セキュリティのため、必ずトークンを無効化してください：
- https://github.com/settings/tokens で該当トークンの「Delete」

## ルール

1. 回答者を希望者から立候補で決める
2. 回答者がカード番号と A〜D を指定（中身は見えない）
3. 他のメンバーには お題が表示される
4. 全員が お題を当てさせるヒントを **1単語** で入力
5. 同じヒントを書いた人がいたら、そのヒントは **無効化**（かぶり消し）
6. 回答者は残ったヒントを見て、**3回まで** お題を答えられる
7. 当たればクリア、3回ミス or 降参で次へ

## セキュリティについて

- トークンはブラウザのlocalStorageに保存され、サーバーに送信されません
- Gistの権限のみのトークンなので、万が一漏洩してもGistの読み書きのみ影響
- Secret Gistは検索されませんが、URLを知っている人なら誰でも閲覧できます
- 機密情報は入力しないでください

### 招待URL方式のリスクと対策

招待URLにはトークンが含まれます。これが漏れると第三者にGistを書き換えられる可能性があります。以下を守れば実質リスクはありません：

- **トークンの権限を「Gist書き込みのみ」に限定**（READMEの手順通り）
- **トークンの有効期限を「翌日」など短期間に設定**
- **イベント終了後に必ずトークンを削除**
- 信頼できる参加者にだけURLを共有（SNS等への公開はNG）

最悪トークンが漏れても：
- Anthropicやリポジトリには影響なし
- 他のGitHubデータには影響なし
- 影響範囲は「そのGist1個のお題データ書き換え」のみ
- イベント後にトークンを削除すれば実害ゼロ

## 技術仕様

- Pure HTML/CSS/JS（ライブラリ・フレームワーク不使用）
- 同期：GitHub Gist API（3秒ごとにポーリング）
- 1時間あたりのAPI上限：5000回（10テーブル×6人で十分余裕）

## トラブルシューティング

### Gist書き込みでエラーが出る
- トークンの権限が「Gists: Read and Write」になっているか確認
- トークンの有効期限が切れていないか確認

### 同期が遅い
- ネットワークが弱い場所では多少遅延します
- 3秒ポーリングなので最大3秒の遅延は仕様です

### 他の人が見えない
- 全員が同じGist IDを使っているか確認
- 同じテーブル番号を選んでいるか確認
